# V1.2 — Language system & QA

## Included languages
Two-column picker matching the supplied reference: left = Arabic, Simplified Chinese, Dutch, English, French, German, Italian, Japanese, Korean; right = Burmese, Russian, Spanish, Thai, Vietnamese. Total 14.

## Language editing
- EN base copy: `data/site-data.js`
- TH copy: `data/site-data.js` (`i18n.th`)
- Other 12 locale packs: `data/extra-locales.js`
- Modal UI: `src/scripts/language-modal.js`, `src/styles/17-language-modal.css`
- Locale resolution: `src/scripts/i18n.js`

## Functional behavior
- Selected language persisted with existing `procleaning-language` localStorage key; honored by the storefront and article, pricing estimate and RFQ entry points.
- Modal keyboard focus and Escape/click-outside behavior; visible flags and native names; responsive two-to-one column.
- Never sends text for automatic machine translation. No translation network API or user data sent externally.
- Admin content editor remains TH/EN; other locales are curated code packs.
- The estimator and RFQ keep technical source labels (English) where curated translations have not been provided; the modal explicitly discloses this. Full article body falls back to English with a notice. Business/CRM and actual quotation PDF are not translated.

## Release notes / risks
- Treat translations as editorial first pass, not certified translations. Obtain native-speaker review for Arabic, Myanmar and legally or commercially sensitive statements before deploying.
- Pricing values are demo-only, no change in calculation logic, terms, VAT or backend connectivity.
- RTL Arabic text blocks are right-aligned while the overall UI grid remains fixed to preserve the source design.
- Native-language font loading uses Google Fonts when online; configure local font licensing separately if offline fidelity is required.
