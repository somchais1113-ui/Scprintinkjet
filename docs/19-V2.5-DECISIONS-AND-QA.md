# V2.5 decisions, risks & manual QA

## Decisions

- Canonical intake: only Smart RFQ API, with lightweight General Inquiry variant for the legacy public Cleaning template.
- The old Contact form with `mailto:` was removed; public CTA goes to `request-quote.html?type=general`.
- Connected mode is **OFF by default**, so users cannot accidentally submit unconfigured forms as if they were live.
- Every accepted RFQ has an unguessable UUID submission idempotency key and human reference.
- A single Postgres RPC inserts customer, RFQ, and notification outbox in one transaction; server's response is authoritative.
- No direct public table writes or browser-stored privileged secrets.
- Staff live inbox is protected by Auth + RLS and stays separate from legacy sample CRM/Quotation Builder/Orders.
- Server-side Cloudflare Turnstile, exact-origin CORS, and hashed short-term email/IP rate limits are included. Configure before real launch.
- Email provider acceptance is distinguishable from database receipt; lost email does not lose RFQ.

## Risks / follow-up

1. **Not connected:** secrets, Supabase project, email domain, Turnstile and DNS must be provisioned by the operator.
2. **Split data:** Existing demo Quote Builder and Orders remain localStorage-only. Next enhancement should implement server-side staff CRUD with audit trail, quotation revisioning and order conversion.
3. **Artwork:** no private file upload in V2.5; add server signed URLs, private bucket and malware preflight later.
4. **Email deliverability:** Resend success means accepted, not delivered. Monitor provider bounces and callbacks.
5. **Bot & abuse:** Turnstile and rate limits reduce risk but do not guarantee safety; add WAF and observation after launch.
6. **PDPA / retention:** draft privacy notice must be replaced, and establish deletion/DSAR/security incident processes.
7. **Web deployment:** do not deploy `.env`, secrets or admin demo with real data to public repository. Review hosting rules.

## Manual browser QA

- In default demo mode: home CTA opens General Inquiry but form explicitly disables real submission. Print Smart RFQ still creates *only synthetic* local demo data.
- With staging configuration: General Inquiry saves into Supabase; Print Smart RFQ saves; Thai/English labels update; no Mail app opens.
- Refresh or double-click with same idempotency token -> at most one DB RFQ; error path doesn't report success.
- Turnstile expiration -> error; re-challenge; retry the same `submission_id`.
- Admin staff login + refresh + logout; non-staff cannot see records; test on mobile.
- Email accepted / provider error / worker retry; no duplicate acknowledgement on rapid requests.
- Run `npm run check` and `npm run check:v25` from project folder.
