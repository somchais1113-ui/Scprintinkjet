# V2.5.4 Hero Layout Regression Fix

## Why the prior display looked wrong
The screenshot is consistent with an HTML/CSS version mismatch (cached old layout CSS), which can leave `.hero__inner` in a horizontal flex layout while HTML is already using separate action row. This cannot be conclusively proven from the screenshot alone. The V2.5.3 structure was also fragile because the main content and button group relied on inherited flex rules.

## Layout contract
- Hero copy stays at the left. Text is never overlaid by the CTA buttons.
- CTA buttons stay below the description.
- Four 6px dots stay at the far right, vertically centered with CTA row.
- No previous / next arrows; dots remain clickable and auto-slide remains enabled.
- All images bleed to the hero edges.
- Small screens may wrap the pagination to a separate row; buttons must remain visible.

## Updating a deployed copy
**Replace the entire site folder** or deploy the entire new commit together. Uploading only `index.html` without the stylesheet is unsafe. The homepage uses `?v=2.5.4` cache-busted asset URLs. Clear your CDN cache if applicable, then hard refresh the website. Inspect Network tab for `10-hero-layout-fix.css?v=2.5.4` HTTP 200.

## Testing
`npm run check` runs the old V2.0–V2.5 checks and new structural checks. Visual acceptance: screenshot at desktop 1440/1714, tablet 768, phones 390/320 for both TH/EN; compare title/button/dot bounding rectangles.
